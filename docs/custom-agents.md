# API Agent 的配置与协作

Lemma 的 API 成员与 CLI 成员使用相同的任务、会话和结果管理流程。成员按职责配置，模型与服务地址决定执行方式；同一模型可以承担多个独立成员。

## 配置与启动

运行 `npm start`，用 `/setup` 引导配置总控，用 `/agent add` 引导添加成员：依次输入成员 ID、名称、职责、专属指令、API 协议、服务地址、模型、工作区与工具权限，最后隐藏输入 API 密钥。已有配置会继续加载，也可用 `PI_AGENT_CONFIG` 指定其他配置文件。

`/agent edit <ID>` 修改 API 成员；`/agent enable|disable <ID>` 启停成员；`/agent model <ID> [模型ID]` 修改默认模型；`/agent key <ID>` 隐藏输入密钥；`/agent show <ID>` 查看配置；`/help` 查看命令。CLI 成员沿用自己的登录，目前支持在终端启停和修改默认模型。

表单输入是本地配置操作，不发送给模型，不加入聊天历史。Enter 确认字段，留空保留当前值；Esc 或 Ctrl+C 取消。配置只在各工作会话都空闲时修改，保存后同步现有工作会话；已运行的成员上下文、数据库与结果保持。启停和配置操作本身不测试服务、不产生模型请求，随后派工才按实际服务计费。

密钥可继续通过配置的环境变量提供，也可以在向导中输入并保存到本机 `~/.lemma/credentials.json`。配置文件仅保存 `credential` 引用，设置本机凭据后该成员使用本机凭据；文件是明文存储，POSIX 下限制文件权限，Windows 下仍需保护用户目录权限。它不属于项目仓库或会话数据库，换机器须重新配置凭据。`LEMMA_CREDENTIALS_FILE` 可显式更换本机存储位置。密钥不写入角色指令、网页响应或模型上下文。

终端与本地管理网页一起启动；`/agents` 查看角色和模型，`/members` 查看成员上下文，Ctrl+K 可只读浏览 API 子对话，`/tasks`、`/jobs` 沿用原有管理命令。网页“成员会话”、成员卡片、派工筛选、统计和拓扑支持自定义成员。网页仍不直接下发任务。

## 如何协作

1. 向总控说明目标、必要资料、约束与验收标准。简单任务可以直接完成；需要分工时，按职责选择成员。
2. 独立任务可同轮并行或放到后台；有依赖的任务由总控在前置结果到齐后继续派发。分工表用于记录依赖，不会自动调度所有节点。
3. 成员在独立会话中处理明确交付的任务，返回报告与结果引用。总控按需读取全文，将下一步所需的证据交给后续成员。
4. 同一工作的追问传回原 `session_id`，只补充变更；独立工作创建新会话，避免无关历史混入。
5. 总控根据验收标准检查结果，记录待验收、完成或受阻状态；需要时继续派工或交给用户判断。运行过程中可以查看进度、取消任务，重启后可恢复对应会话。

默认成员只接收任务里明确交付的资料，不自动读取电脑里的文档，也不复制总控整段聊天。需要读取本地文件时，可给对应成员配置 `api.tools: ["read"]`，并在任务里交付相对路径。

## 成员配置

`agents` 的键是成员 ID，可以使用小写字母开头，后接小写字母、数字或下划线，最多 48 个字符；系统保留名不能使用。它用于任务、会话和历史记录，已运行后不建议随意重命名。

| 字段 | 含义 |
|---|---|
| `name` | 终端与网页显示的角色名称 |
| `description` | 总控据此选择成员，说明适合处理的任务 |
| `instructions` | 该成员专属指令，进入它自己的系统上下文 |
| `models` / `defaultModel` | 允许使用的模型与默认模型；API 成员未指定默认时取清单第一项 |
| `api.type` | `openai-compatible` 或 `anthropic-compatible` |
| `api.baseUrl` | 对应协议的服务地址；不能在 URL 中放用户名或密码 |
| `api.apiKeyEnv` | 按顺序读取凭据的环境变量名 |
| `api.credential` | 终端自动保存的本机凭据引用；不是密钥原文 |
| `api.tools` | 显式授予 `read`、`write`、`edit`、`bash` 中的工具；自定义成员默认 `[]` |
| `api.httpTools` | 仅授权给该成员的 HTTP 业务工具；固定端点、参数 JSON Schema、GET/POST 与凭据引用 |
| `api.bash` / `bashAllow` | shell 的额外开关和命令白名单；默认关闭，即使列入 tools 也要明确开启 |
| `workspace` | `none`：领域对话/工具协作；`code`：已有代码工作区流程 |
| `timeoutMinutes` / `api.maxTurns` | 单次派工超时、最多工具轮数 |
| `maxOutputChars` | 自动回传的预览长度；全文另行持久保存 |
| `models[].price` | 每百万 token 的价格，只有配置或服务报告时才能可靠统计费用 |

`collaboration.instructions` 为总控、子调度及 API 成员提供共同领域说明；`roles` 将业务岗位映射到成员 ID。纯非代码团队没有配置 roles 时，不自动套用默认编码角色表；混合团队保留原有默认角色，也可显式配置 `roles` 或设为 `[]`。

同一模型可以承担多个 Agent：每个成员有自己的 provider 注册名、系统指令、工具权限和独立会话。不同成员也可以配置不同服务地址、凭据、协议与模型，混合使用。新成员使用 `ask_<成员ID>` 工具（例如 `ask_analyst`），沿用同步、同轮并行和 `background: true` 的已有派工方式。

## 工作区与兼容性

- 自定义 API 成员默认 `workspace: "none"`：不创建 worktree、不执行 Git 快照与提交、不运行代码检查/自动代码修复，也不装入编码规范或编码修复经验。即使全局打开代码隔离/代码验收，这些成员也不会套用它们。
- `workspace: "none"` 的成员拒绝 `based_on`。跨成员交接应传必要资料与结果片段；总控可用 `read_result` 取回省略证据，再交付给下一成员。
- 显式开启文件写入并不提供文件系统隔离；非代码成员的文件工具作用于配置工作目录，可能修改原文件。文件路径访问沿用既有检查，shell 权限沿用既有白名单机制，不等于 OS 沙箱。
- 旧的 `claude`、`codex`、`gemini`、`deepseek` 配置继续加载，默认保留 `workspace: "code"` 和原有权限约定。自定义 API 成员也可显式选择 code；内置 CLI 暂不提供非代码执行模式。
- 没有启用的成员不会启动。演示模式会禁用自定义真实 API 成员，只运行已有模拟剧本，避免误请求。

## 会话与任务闭环

每次新派工在 Durable 中创建任务拥有的独立 API 子对话，返回 `session_id`；同一工作的增量追问传回该 ID。成员与总控归属检查、预算、超时、取消、后台任务和重启恢复沿用同一条执行链路。重启不会另建一套会话系统；未完成的 API 派工通过任务所有权与幂等 requestId 找回，已完成记录不丢。

总控收到限长报告与 `result_id`，通过 `read_result` 分页读取原文，完整聊天仍在成员子对话中。域内任务也支持 `plan_tasks → ask_* → wait_jobs → update_task`；成员成功返回只代表执行完成，任务先进入待验收，由总控根据验收标准核对。

任务可以在 `plan_tasks` 中预设 `checks`：`contains` 检查报告全文包含文本；`json_exists` 检查完整 JSON 报告的点分字段路径；`json_equals` 将字段与 JSON 文本解析后的值比较。`value` 在 contains 中是文本，在 json_equals 中是 JSON 文本（例如字符串需带 JSON 引号）。这些规则验证结构与明确字段，不能证明业务事实、审批有效性或资料真实性；仍需总控、复核成员或人工核对依据。

成员返回后自动对**完整结果**计算机器检查，任务保持待验收。`review_task` 用最新 `result_id` 执行 `check`、`accept`、`rework` 或 `block`；除 check 外必须提供 evidence。accept 需要成功执行、规则通过且依赖任务均已验收。首次派工后锁定验收标准；不能通过降低标准、验收旧结果或直接 update_task done 绕过机器规则。返工记录缺口并退回待办，由总控决定是否续接原 session_id，不会无限自动重试。

跨成员交接支持 `ask_*` 的 `inputs: [{ result_id, offset, limit }]`，从同一总控的结果存储中直接提取原文和来源；每次最多 8 个片段，每片最多 8000 字符，默认 2000。无需手工复制成员整段聊天。存在 deps 的任务须等前置任务完成验收后才可派工。

`/tasks`、网页看板与 ASSIGN.md 显示最新结果、机器检查与复核证据；`/result <result_id> [偏移]` 在终端直接分页查看全文，不调用模型。执行异常、超时及取消保留已有成员会话；正常收尾会保存失败结果，失败受阻、取消退回待办。进程关闭和崩溃继续由 Durable 原有恢复路径管理。代码验收与有限代码修复仍保留，业务验收不能绕过已有代码检查。预算按已报告或配置定价的花费执行，缺少价格/usage 时不能视为完整成本上限。

## 在终端接入业务工具

启动 `npm start` 后输入 `/tool add <成员ID> [工具ID]`。向导填写用途、固定 HTTP(S) 地址、GET/POST、参数 JSON Schema；POST 可配置**服务实际支持**的幂等请求头，最后隐藏输入可选 Bearer 密钥。无需先写适配器代码，模型只填写业务参数，不选择地址或认证头。`/tool list`、`/tool edit`、`/tool key`、`/tool remove` 均带成员 ID，后三者再带工具 ID。工具配置在空闲时生效，移除授权保留历史。

GET 将简单字段编码为查询参数；POST 发送 JSON 对象。凭据支持环境变量或本机凭据引用；响应中出现相同凭据原文时会脱敏。请求跟随任务取消，超时默认 30 秒，不跟随重定向；响应超过 128 KiB 返回错误，交给模型的文本默认最多 8000 字符，超出会明确标识截断。工具访问固定配置地址；配置本地/内网接口即表示允许该成员调用该接口。

GET 可在进程恢复时重放；未配置幂等支持的 POST 使用 Durable 原生 replay=unsafe，中断后不自动重放；配置幂等请求头时使用稳定的调用标识。POST 超时或断网可能已在远端生效，需要核对远端状态，不能宣称撤销成功。含 POST 工具的成员不进入代码自动重试流程；领域业务返工由总控带依据决定。

## 当前范围

本次交付：任意 API 成员 ID、角色指令、两类已有 API 协议、显式文件/shell 工具授权、非代码执行路径、现有界面的动态成员目录，以及并行、后台、隔离、续接、取消和进程恢复。

当前还不支持 MCP 连接器向导、OAuth 流程、任意自定义认证头、单个 Agent 内部的多模型工作流，以及判断所有行业事实的自动验收器。外部 POST 不提供跨系统事务或自动回滚；行业数据源、业务规则与远端幂等能力仍由实际服务提供。

测试：`npm run test:custom-agents`。测试使用本机固定响应 HTTP 服务，实际走现有模型协议适配器、Durable 与应用宿主；不请求真实模型、不产生服务费用，不等于行业输出质量评测。

业务工具与验收回归：`npm run test:business`；终端配置回归：`npm run test:settings`。覆盖原生 Durable 调用 HTTP、权限与密钥、失败/取消/超时、规则锁定、旧结果拒绝、明确返工与原文交接。
